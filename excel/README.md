# Excel workbook

`booking_curves.xlsx` works on its own: open it, change the yellow cells on the
Curves sheet, and the table and charts recalculate. No macros, add-ins,
connections or internet access.

It is generated by `scripts/build_workbook.py`. Every number comes from SUMIFS
formulas over the Data sheet, which holds the table `mart_booking_curve_compact`
produced by `sql/marts/booking_curve.sql`.

## What has and has not been tested

- Formulas: recalculated in LibreOffice and checked against the SQL mart
  (for example City Hotel, 30 days out: 112,721 net room-nights on the books).
- Not tested: opening in Excel 365 itself, the two charts' appearance in Excel,
  and both Power Query files. The first run in Excel is the real test.

## Five-minute check in Excel

1. Open the workbook. Curves!B15 should read 134,899 and C15 119,375.
2. The row for 30 days out should show 112,721 (A) and 98,705 (B) net on the books.
3. Change B5 to `All` and B6 to `GROUP`. Series A's "% of final stayed" should sit
   above 100% far out and fall toward 100% at the stay night.
4. Both charts should show two lines, far out on the left and the stay night on the right.

## Pointing it at other data

The Curves sheet only needs ten columns on the Data sheet, in this order:

`property_code, stay_year_month, is_fri_sat, business_source, days_before_stay,
rn_booked, rn_canceled, rn_stayed, rev_booked, rev_canceled`

Three ways to fill it, simplest first:

1. **Paste.** Run the SQL, export `mart_booking_curve_compact`, paste over the Data sheet.
2. **Power Query from CSV.** `queries/curve_from_csv.pq`, with the folder set in Settings!B2.
3. **Power Query from SQL.** `queries/curve_from_sql.pq`, with server and database in Settings!B3:B4.

Then update the Lists sheet if the property or source-of-business codes differ,
and set the stay-month range on the Curves sheet.

Private data stays private this way: the workbook, the SQL and the query files
contain no data of their own beyond the public sample, and nothing calls out
to any service.
